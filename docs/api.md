# API Reference

The full **C++ API reference** is generated by Doxygen via [mkdoxy](https://mkdoxy.kuba--. pages.dev/) and lives in the [C++ API](cppapi/annotated.md) section. This page gives an overview of the public API.

## Namespaces

```
Mycila::HA
├── Device                          device identity attached to all entities
├── Category (enum)                 entity category: NONE, CONFIG, DIAGNOSTIC
├── StateClass (enum)               sensor state class
├── NumberMode (enum)               number input mode: AUTO, BOX, SLIDER
├── Component (base class)
│   ├── Button, Switch, Outlet, Select, Text, Number
│   ├── Climate, Cover, Fan, Valve, Humidifier
│   ├── Date, Time, Datetime, Notify, Siren
│   ├── Lock, WaterHeater, DeviceTracker, Light, Update
│   ├── State (binary_sensor)
│   └── Sensor → Gauge, Counter, Total, Value, Enum
└── Discovery                       publishes and unpublishes components
```

## Device

| Field | Type |
| :-- | :-- |
| `id`, `name`, `version`, `model`, `manufacturer`, `url` | `std::string` |

## Discovery

| Method | Description |
| :-- | :-- |
| `Discovery(Device, std::string baseTopic, PublisherCallback)` | Store device, base topic and publisher callback |
| `setDiscoveryTopic(std::string)` | Change the discovery prefix (default `homeassistant`) |
| `setWillTopic(std::string)` | Global availability topic (LWT) |
| `publish(std::unique_ptr<Component>)` | Allocate, serialize and publish the component; frees it when done |
| `publish<T>(Args&&...)` | Convenience overload: constructs `T` in place with `make_unique` |
| `unpublish(std::unique_ptr<Component>)` | Publish an empty payload to the component discovery topic |
| `unpublish<T>(Args&&...)` | Convenience overload |
| `end()` | Clears the publisher callback |

`PublisherCallback` is `std::function<void(const char* topic, const std::string& payload)>`.

## Component base fields (all components)

| Field | Type | Description |
| :-- | :-- | :-- |
| `type` | `const char*` | HA platform name (`sensor`, `light`, ...) |
| `id`, `name` | `std::string` | Entity identity and display name; owned |
| `deviceClass`, `icon` | `const char*` | Borrowed metadata |
| `category` | `Category` | Entity category |
| `configTopic` | `std::string` | Full discovery topic override, including `/config` |
| `uniqueId` | `std::string` | Auto-filled with `<device_id>_<id>` on first publish |
| `defaultEntityId` | `std::string` | Auto-suggested `<type>.<device_id>_<id>`, slugified |
| `enabledByDefault` | `std::optional<bool>` | `enabled_by_default` |
| `useDeviceAvailability` | `bool` | Include the will topic in per-component availability |
| `availabilityTopic` | `std::string` | Per component availability |
| `availabilityTemplate` | `const char*` | Availability value template |
| `payloadAvailable`, `payloadNotAvailable` | `const char*` | Availability payloads |

Per-platform fields (topics, payloads, templates, bounds) are documented on each [component page](components/index.md) with the Home Assistant option names.
